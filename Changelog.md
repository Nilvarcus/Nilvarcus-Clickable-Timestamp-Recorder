# Changelog

## MVP — Clickable Timestamp Recorder

- Added a recording-stop marker: when a recording ends (OBS stop or the in-app ■ toggle), a dim `■ Recording stopped — HH:MM:SS` row appears at the bottom of that recording segment in the timestamp list, and each finished segment's Markdown section gains an italic `_Recording stopped — HH:MM:SS_` line. The duration comes from the segment's existing `started_at`/`ended_at` timestamps (no session-format change), persists across restarts for past segments, and live segments show no footer while running; a newly appearing footer participates in smart-follow scrolling like any other list change.
- Fixed the compacted timestamps view rendering broken: the layout refactor left the list frame's expansion weight on its row 0 (the toolbar row), so all spare vertical space went to an empty gap around the ▶/＋/Manual buttons while the timestamp list stayed squashed to its ~200 px default height. The weight now sits on the list's row, so the buttons hug the top-right above a full-height, tightly stacked list that grows and shrinks with the window. Also fixed the empty chip container (meta_frame) defaulting to CTkFrame's built-in 200×200 px size, which made every empty-label/no-tag row 200+ px tall instead of ~28 px. No behavior changed.
- Compacted the whole main window: the header is now a single row (title, REC indicator, clock, OBS status, Tags, Connect), project/microphone/folder/hotkey settings fit in two rows (the output-folder path is elided so long paths cannot push controls out of view, and the permanent hotkey hint moved into the capture button's "Press a key or mouse button… (Esc cancels)" text), and each timestamp renders as one thin row — colored state dot, `R##-###` reference plus time, inline label and up to three tag chips (+N overflow) — instead of a tall two-line button. The whole row stays clickable with the same record/stop/play behavior, ✎/✕/🎬 mini icons sit at the row end, and the default window shrank from 760×680 to 720×560. No behavior changed: timer gating, screenshots, replay logging, hotkeys, dialogs, and persistence are untouched.

- Deleting a timestamp now cleans up after itself: the entry's WAV file and screenshot JPEG are deleted from disk along with the log entry instead of being left behind. The confirmation dialog warns which files will be deleted, a locked or undeletable file never blocks removing the entry and is reported in the status bar instead, paths outside the project folder are never touched, and deleting an entry while its screenshot is still capturing removes the freshly written JPEG too. Replay entries lose only their microphone-note WAV — the linked OBS replay video stays on disk as before.
- Fixed UI flickering when taking timestamps or clicking around: the timestamp list used to destroy and recreate every row widget on each interaction (twice per timestamp — creation plus the screenshot-attach callback), which visibly blinked the whole scroll area on Windows. List refreshes are now coalesced so a burst of state changes produces one repaint ~30 ms later, and rows/section headers are cached per entry id and reconfigured in place — widgets are only created or destroyed when entries or segments actually appear or disappear. Rendering output is unchanged.
- Fixed OBS reconnect churn: with obsws-python 1.x the auto-reconnect watchdog's socket-liveness probe read a client attribute path that no longer exists (`event.ws` moved to `event.base_client.ws`), so every ~5 s cycle tore down a healthy connection while OBS was recording — stopping the timer, reconnecting, and starting a brand-new recording segment each time. The probe now resolves the WebSocket across old and new library layouts, checks its `connected` flag, and fails open (assumes alive) on any unrecognized layout so future library changes can never restart recordings again; genuine OBS exits are still detected within one watchdog pass.
- Added a tag library: the 🏷 Tags button in the header (or ＋ New tag inside the timestamp edit dialog) opens a manager to create custom tags with palette/custom colors, rename, recolor, and delete them. Renames and deletes propagate to all timestamps in the open project — list chips, Markdown log, and `session.json` — with a confirmation before removing an in-use tag; every change persists to `keybinds.json` immediately. Hand-edited `tags` configs load unchanged.
- Added automatic OBS connection: when `obs_settings.auto_connect` is on (now the default for new/missing keys), a watchdog connects immediately, retries about every 5 seconds while OBS is closed behind an amber `● Waiting for OBS…` indicator (failures logged to console only), detects a connection that died because OBS exited, and reconnects automatically when OBS starts again. Clicking Disconnect pauses auto-connect until Connect OBS is clicked; set `auto_connect: false` for manual-only behavior.

- Added automatic OBS replay-buffer logging: each `ReplayBufferSaved` event creates a violet 🎬 REPLAY entry inline between timestamps, tagged with the OBS replay file's name and linking to its video (`Footage:` line in Markdown, 🎬 row button to open it). Replay entries support microphone notes, labels/tags, and deletion like timestamps; saving the same replay twice never duplicates; saves while the timer is stopped attach to the most recent segment; no screenshots are captured for them. Requires OBS replay buffer enabled; replays saved before connecting are not backfilled.
- Session format bumped to version 6 with the optional `kind`/`replay_file` fields; version 1–5 files load unchanged (entries without `kind` load as regular timestamps).
- Added recent projects: clicking the project-name field opens a popup with the five most recent projects for one-click loading; the list persists in `keybinds.json`.
- Added a built-in ▶/■ timer so timestamps and microphone notes work without OBS running; stopping the timer locks new-timestamp creation exactly like an OBS stop, while existing rows stay recordable and playable when locked.
- Added per-timestamp screenshots: every new timestamp captures a 720p-height JPEG of the main monitor into the project's `Screenshots/` folder, embedded in the Markdown log directly below its entry; capture failure never blocks timestamp creation and JPEG files are never deleted.
- Session format bumped to version 4 with the optional per-timestamp `screenshot_file` field; version 1–3 files load unchanged.

- Added per-recording timestamp grouping: every OBS recording opens a numbered segment named after the OBS recording file, timestamps display as `R##-###` and restart at 001 each recording, and the Markdown log gains one section per recording.
- Session format bumped to version 3 with recording segments and per-timestamp segment stamps; version 1/2 files load unchanged with their entries shown under "Earlier timestamps".
- New WAV files are named `R##-###_HH-MM-SS.wav`; existing files keep their names.
- Added timestamp labels and preset tags (`keybinds.json`), editable through a per-timestamp dialog.
- Added timestamp deletion: the log entry is removed and the WAV file stays on disk.
- Added manual timestamps created from typed time positions (SS, MM:SS, or HH:MM:SS).
- Session format bumped to version 2 with optional label/tag fields; version 1 files load unchanged.
- Simplified the application to OBS-synchronized clickable timestamps.
- Added project names, project folders, Markdown logs, and JSON session metadata.
- Added microphone device selection and WAV recording/playback.
- Added configurable global timestamp hotkey.
- Bundled the sounddevice PortAudio runtime in the PyInstaller executable.
- Removed Gemini, screenshot, HUD, DaVinci Resolve, replay-buffer, video, and transcription features from the active application.
