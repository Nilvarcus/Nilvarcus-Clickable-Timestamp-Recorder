# Changelog

## 1.0.2

- Vertical Backtrack replay entries now locate their clip by the save time embedded in the file name (`Backtrack [DD-MM][HH-MM-SS]` — day-month, local clock), scanning the save folder's subfolders like `Replay Buffer\` where the plugin actually drops clips, instead of relying on top-level file mtime alone. The vertical recording's own file (`[DD-MM][HH-MM-SS]-vertical.mp4`, actively rewritten during recording, so it always had the newest mtime and was repeatedly mis-resolved as the replay) is excluded from both selection paths — by its queried recording path and its `-vertical` name suffix — so a save without a locatable clip degrades to the amber "path unavailable" status instead of a wrong video; only non-recording, unparseable-name files still fall back to the newest-recent-mtime rule.

- Added Aitum Vertical (obs-vertical-canvas) recording support: the plugin records through its own output that never fires OBS's standard RecordStateChanged event, so vertical recordings previously did nothing to the app. `OBSManager` now listens for the plugin's obs-websocket vendor events (`aitum-vertical-canvas` vendor): a vertical recording start (dock button or hotkey) starts the timer and opens a segment exactly like a main recording, and stopping it finalizes the segment. Main and vertical recordings merge into one combined session — the timer runs while *either* is active, an overlapping start does not reset it, and it stops only when both stop. Vertical segments get the real video file name by reading the `vertical_canvas_record` output's settings over the WebSocket (stop events backfill it; failure degrades to an unnamed segment). Vertical **Backtrack** saves (`backtrack_saved`) are logged as 🎬 REPLAY entries, with the clip located by scanning the Backtrack save folder (from the plugin's replay output settings) for the newest video modified within ~15 s of the save. Connecting mid-recording syncs vertical state via the plugin's `status` vendor request; without the plugin installed the request fails once silently and nothing changes. Names are pinned to Aitum Vertical 1.6.x (Aitum Stream Suite is not covered).

- Fixed screenshots capturing the wrong monitor: `capture_to_path()` grabbed mss `monitors[1]`, assuming the OS primary display is enumerated first — on Windows the order is undefined and on multi-monitor setups the secondary often landed at index 1. A new pure `select_primary_monitor()` helper picks the primary by mss's `is_primary` flag when present, otherwise by virtual-screen origin `(0, 0)` (where the OS primary always sits), falling back to `monitors[1]` only in degenerate layouts; verified live on a three-monitor machine where the primary sat at index 3.
- Replay entries now show their audio state at a glance in the main list: an amber dot with `· no audio — click to record` while the clip has no saved take, red while recording or after a failed take, and green with `· audio N.Ns` once a take exists (blue ■ stop while playing) — violet is retired as the replay row color; identity stays with the `REPLAY` text and 🎬 button. Replays also gained the 🎙 quick-take button (■ Stop while capturing) for re-recording without the edit dialog, and a new **Missing audio** checkbox beside the 🔍 filter box filters the list to replays without a saved take (hidden rows stay cached, a fully-filtered list shows a "No replays missing audio 🎉" placeholder, and switching projects resets it).

- Performance: long sessions (~200 timestamps) no longer repaint themselves on every interaction. List refreshes now carry a full per-row signature (status, error, duration, audio/screenshot files, take count, playing state, label, tags, elapsed time), so a refresh only reconfigures rows whose entry actually changed — one-row or no-change refreshes dropped from ~700–800 ms to ~0.2–3 ms in a 200-entry test project. Grid calls, section-header labels, and stop-footers follow the same skip-if-unchanged rule, section grouping is a single pass (O(entries) instead of O(recordings × entries)), playing-state comparison resolves the playback path once per refresh instead of per row, and smart-follow scrolling stopped calling `canvas.update_idletasks()` (the app-wide layout pass that made adding a row to a long list feel heavy) in favor of chained idle passes — verified to still land the view on the newest entry.
- Performance: the Markdown project log (derived data) is now debounced while `session.json` stays synchronous on every mutation. `TimestampSession` gains `markdown_autoflush` (default `True` — tests and direct consumers keep today's synchronous behavior; the GUI sets `False`) and `flush_markdown()`; the GUI coalesces bursts into one Markdown write ~1 s after the last change and flushes immediately before closing the app, switching projects, or dropping the session, so the log on disk never lags a destructive operation.

## 1.0.1

- Removed the in-app header title text ("Clickable Timestamp Recorder"): it duplicated the OS window bar and added nothing to the UX, so the header strip now keeps only its controls — REC indicator, clock, OBS status, 🏷 Tags, ⚙, Connect OBS — right-aligned with blank space on the left. The window/taskbar title was renamed to **Nilvarcus Clickable Timestamp Recorder**.

- Fixed the recent-projects popup staying behind when the main window is moved or resized while it is open: the popup now re-anchors itself under the project-name field in real time via a root `<Configure>` listener (kept inside the window bounds by the same clamp/flip rules as before), and minimizing (unmapping) the main window dismisses it so an orphaned borderless popup can never linger on screen.
- Added a quick **🎙 record-another-take** button to completed timestamp rows: one click starts recording the next take straight from the main list — no edit dialog needed — and the button becomes **■ Stop** while that row captures; stopping saves the file as the new active take exactly like an in-dialog re-record (the `🎙 N takes` chip updates on its own). Pending/error rows hide the button, replay entries never get one, and starting while another recording runs still shows the amber "Stop the current timestamp recording first" hint. As part of this, an aborted retake (silence auto-stop or recorder error) now returns a taken entry to its completed state with the previous active audio intact instead of wrongly regressing it to grey pending.
- Fixed silence auto-stop deleting voiceover takes after a pause: the watchdog now fires only when a recording contains **no** microphone input at any point from start to finish (dead/muted mic). The first chunk at/above the threshold permanently disarms the auto-stop for that take, so pausing mid-VO — even past `mic_settings.silence_timeout` — never discards audio you already recorded; manual stop keeps working as before.
- Added in-app OBS connection settings (⚙ button next to Connect OBS): host, port, password (masked with Show/Hide), and auto-connect toggle in an `ObsSettingsDialog` with header ✕, **Save**/**Cancel**, and **Esc** to close. Saving persists to `keybinds.json` and reconnects immediately; auth failures (wrong password) are now detected for both manual and watchdog attempts and surface as a red `● OBS auth failed` header plus a status-bar hint ("OBS refused the password — click ⚙ to edit"), de-duplicated so repeated retries stay quiet, while generic waiting failures remain amber.
- Added a toolbar filter (🔍) above the timestamp list: live substring search across label, `R##-###` ref, `HH:MM:SS` time, and tag names; fully-filtered shows "No timestamps match" and hides empty segments, partially-filtered hides only non-matching rows (cached but `grid_remove`d), and switching projects clears the filter. The empty placeholder is now contextual (no project / timer stopped / ready / filtered).
- Editable timestamp times: the ✎ dialog now has a HH:MM:SS/MM:SS/SS field (prefilled, validated via `parse_time_input`), persisted via new `TimestampSession.update_entry_time()` (same segment, no file rename).
- Added project rename (✎ button in each recent-projects row, next to 🗑): prompts for a new name, sanitizes, blocks the open project and collisions, renames the folder, markdown file, and `session.json` project_name (missing folders degrade to list-only), then rebuilds the popup. Recent entries now store the project folder directly (with `_resolve_project_folder` handling legacy base-stored entries) and `_recent_row_text` shows live counts from the resolved folder.
- Manual-timer pause: toolbar now shows ⏸ Pause (→ ▶ Resume while paused) when the timer runs; it is disabled while OBS drives the recording. `TimestampSession` gains `timer_paused`, `pause_timer()`/`resume_timer()` (epoch shifted by paused duration so future timestamps continue from the frozen time, segment wall duration still includes pause), `elapsed_seconds()` freezes while paused, clock shows amber `● PAUSED N`, and new-timestamp creation is blocked until resumed. Pause does not survive a restart.
- Deleting a timestamp now recycles its WAV takes and screenshot to the Recycle Bin (`_recycle_project_file` via `send2trash`); if a file is locked the entry is kept and the status bar reports the problem so the user can retry (paths outside the project folder are reported but do not block deletion, preserving the out-of-project test). Previously locked files were deleted via `os.remove` and reported but never blocked removal.
- `TimestampSession.save()` now keeps a one-generation backup (`session.backup.json`) before writing `session.json`, so "restore from backup" is a real file.
- Fixed timestamp edit dialog clipping where **Save**/**Cancel** were invisible: dialog now pins the footer with `pack(side="bottom")` and gives the takes list `fill="both" expand=True` (height 110) so the buttons stay visible even when the tag chips or window clamp (`window-24`) would otherwise push them off-screen; also tightened paddings so the new Time field fits within the 540 px card.

- Fixed timestamp edit dialog playback: takes now show a ▶/■ toggle that flips to ■ Stop while a take is playing and is stoppable by clicking again; the dialog row refreshes immediately on play and again on stop/finish, and the main list dot/label also updates. Previously pressing ▶ appeared stuck with no affordance to stop.
- Added an Open screenshot button to the timestamp edit dialog header (📷 Screenshot, enabled only when the entry has an attached screenshot; replay entries keep it disabled; uses the same OS opener and error handling as the row 📷 button and enables live when the async capture finishes while the dialog is open).
- Fixed WAV/screenshot collision naming stacking suffixes (`_2_3` → `_3`): `TimestampSession._unique_path` now appends `_N` to the original stem instead of the previous candidate, so `audio_path` and `screenshot_path` produce flat `_2`, `_3`, `_4` sequences. Existing stacked files are left as-is.

- Fixed microphone notes being cut off after a few seconds when OBS was not running: the auto-reconnect watchdog's "waiting" status (repeated every ~5 s while OBS is unreachable) force-finalized any running timer and saved whatever partial audio existed, which made offline voiceover work effectively impossible — the ▶ timer and recordings were killed within seconds of starting. The watchdog now finalizes an active session only on a real connected→dropped transition; with OBS simply off, manual sessions run indefinitely. A genuine OBS exit mid-recording still finalizes the note exactly as before.
- Added re-recordable takes: every timestamp can hold multiple audio takes instead of one final WAV. The edit dialog gains an **Audio takes** section listing them newest-first with play (**▶**), make-active (**★ Use**), and delete (**🗑**, confirmed) actions per take, plus a **🎙 Re-record** button that records the next take right in the dialog (the form locks while recording; closing it mid-take leaves the row clickable to stop). Each new take becomes the active headline audio; rows show a `🎙 N takes` chip when more than one exists; the Markdown log lists non-active takes under the entry; deleting the last take returns the entry to its recordable pending state. `session.json` stores the optional per-entry `takes` list; older files load unchanged (existing audio becomes take 1) and retake files keep unique names (`_2`, `_3`, …).
- Added a live microphone level meter with silence detection: a small 🎤 bar beside the status bar appears during any recording (first note or re-record alike) so dead-mic situations are visible immediately. If no input above the configured threshold arrives for the timeout period, the capture stops automatically, nothing is written to disk, the entry returns to clickable-pending, and the status bar says "No microphone input detected — check the selected mic and try again." Threshold (`mic_settings.silence_threshold`, default RMS 250) and timeout (`mic_settings.silence_timeout`, default 5 s) are configurable in `keybinds.json`.

- Added per-segment main-recording access: every recording section header in the timestamp list now shows a small 📼 button that opens that segment's OBS recording video with the OS default player, and each segment header in the Markdown log gains a `Footage:` file link so recordings are reachable from Obsidian too. The app keeps the absolute video path OBS already reports in its record start/stop events (`RecordingInfo.path` persisted in `session.json`; older files load unchanged — the start event fills it, the stop event confirms it). Buttons stay greyed for segments without a known path (in-app timer-only sessions, older sessions) and a missing video reports an error in the status bar; no new OBS requests are made and nothing new is deleted.

- Hardened the recent-projects picker: rows now show each project's activity — `N timestamps · M recordings`, read from its `session.json` — instead of a truncated folder path, and every row gained a 🗑 delete button that moves the project's folder to the Recycle Bin (via the new `send2trash` dependency) after a confirmation and only then removes the list entry. The folder is recycled first, so a locked or failed delete never leaves a stale entry pointing at live files; entries whose folder already vanished show a dim `(folder missing)` marker and degrade to removing just the list entry; the currently open project refuses deletion until another one is selected; and the popup rebuilds in place after each delete so several projects can be cleaned out in one pass.
- Screenshot embeds in each project's Markdown log now use Obsidian wikilink syntax with just the filename (`![[R02-005_00-00-19.jpg]]`) instead of standard image syntax with a folder path (`![Screenshot](Screenshots/...)`), so they render directly inside Obsidian vaults without any folder prefix. Storage, capture, and `session.json` are unchanged; existing projects regenerate into the new format on their next save.

## MVP — Clickable Timestamp Recorder

- Added a recording-stop marker: when a recording ends (OBS stop or the in-app ■ toggle), a dim `■ Recording stopped — HH:MM:SS` row appears at the bottom of that recording segment in the timestamp list, and each finished segment's Markdown section gains an italic `_Recording stopped — HH:MM:SS_` line. The duration comes from the segment's existing `started_at`/`ended_at` timestamps (no session-format change), persists across restarts for past segments, and live segments show no footer while running; a newly appearing footer participates in smart-follow scrolling like any other list change.
- Fixed the compacted timestamps view rendering broken: the layout refactor left the list frame's expansion weight on its row 0 (the toolbar row), so all spare vertical space went to an empty gap around the ▶/＋/Manual buttons while the timestamp list stayed squashed to its ~200 px default height. The weight now sits on the list's row, so the buttons hug the top-right above a full-height, tightly stacked list that grows and shrinks with the window. Also fixed the empty chip container (meta_frame) defaulting to CTkFrame's built-in 200×200 px size, which made every empty-label/no-tag row 200+ px tall instead of ~28 px. No behavior changed.
- Compacted the whole main window: the header is now a single row (title, REC indicator, clock, OBS status, Tags, Connect), project/microphone/folder/hotkey settings fit in two rows (the output-folder path is elided so long paths cannot push controls out of view, and the permanent hotkey hint moved into the capture button's "Press a key or mouse button… (Esc cancels)" text), and each timestamp renders as one thin row — colored state dot, `R##-###` reference plus time, inline label and up to three tag chips (+N overflow) — instead of a tall two-line button. The whole row stays clickable with the same record/stop/play behavior, ✎/✕/🎬 mini icons sit at the row end, and the default window shrank from 760×680 to 720×560. No behavior changed: timer gating, screenshots, replay logging, hotkeys, dialogs, and persistence are untouched.

- Deleting a timestamp now cleans up after itself: the entry's WAV file and screenshot JPEG are deleted from disk along with the log entry instead of being left behind. The confirmation dialog warns which files will be deleted, a locked or undeletable file never blocks removing the entry and is reported in the status bar instead, paths outside the project folder are never touched, and deleting an entry while its screenshot is still capturing removes the freshly written JPEG too. Replay entries lose only their microphone-note WAV — the linked OBS replay video stays on disk as before.
- Fixed UI flickering when taking timestamps or clicking around: the timestamp list used to destroy and recreate every row widget on each interaction (twice per timestamp — creation plus the screenshot-attach callback), which visibly blinked the whole scroll area on Windows. List refreshes are now coalesced so a burst of state changes produces one repaint ~30 ms later, and rows/section headers are cached per entry id and reconfigured in place — widgets are only created or destroyed when entries or segments actually appear or disappear. Rendering output is unchanged.
- Fixed OBS reconnect churn: with obsws-python 1.x the auto-reconnect watchdog's socket-liveness probe read a client attribute path that no longer exists (`event.ws` moved to `event.base_client.ws`), so every ~5 s cycle tore down a healthy connection while OBS was recording — stopping the timer, reconnecting, and starting a brand-new recording segment each time. The probe now resolves the WebSocket across old and new library layouts, checks its `connected` flag, and fails open (assumes alive) on any unrecognized layout so future library changes can never restart recordings again; genuine OBS exits are still detected within one watchdog pass.
- Added a tag library: the 🏷 Tags button in the header (or ＋ New tag inside the timestamp edit dialog) opens a manager to create custom tags with palette/custom colors, rename, recolor, and delete them. Renames and deletes propagate to all timestamps in the open project — list chips, Markdown log, and `session.json` — with a confirmation before removing an in-use tag; every change persists to `keybinds.json` immediately. Hand-edited `tags` configs load unchanged.
- Added automatic OBS connection: when `obs_settings.auto_connect` is on (now the default for new/missing keys), a watchdog connects immediately, retries about every 5 seconds while OBS is closed behind an amber `● Waiting for OBS…` indicator (failures logged to console only), detects a connection that died because OBS exited, and reconnects automatically when OBS starts again. Clicking Disconnect pauses auto-connect until Connect OBS is clicked; set `auto_connect: false` for manual-only behavior.

- Added automatic OBS replay-buffer logging: each `ReplayBufferSaved` event creates a violet 🎬 REPLAY entry inline between timestamps, tagged with the OBS replay file's name and linking to its video (`Footage:` line in Markdown, 🎬 row button to open it). Replay entries support microphone notes, labels/tags, and deletion like timestamps; saving the same replay twice never duplicates; saves while the timer is stopped attach to the most recent segment; no screenshots are captured for them. Requires OBS replay buffer enabled; replays saved before connecting are not backfilled.
- Session format bumped to version 6 with the optional `kind`/`replay_file` fields; version 1–5 files load unchanged (entries without `kind` load as regular timestamps).
- Added recent projects: clicking the project-name field opens a popup with the five most recent projects for one-click loading; the list persists in `keybinds.json`.
- Added a built-in ▶/■ timer so timestamps and microphone notes work without OBS running; stopping the timer locks new-timestamp creation exactly like an OBS stop, while existing rows stay recordable and playable when locked.
- Added per-timestamp screenshots: every new timestamp captures a 720p-height JPEG of the main monitor into the project's `Screenshots/` folder, embedded in the Markdown log directly below its entry; capture failure never blocks timestamp creation and JPEG files are never deleted.
- Session format bumped to version 4 with the optional per-timestamp `screenshot_file` field; version 1–3 files load unchanged.

- Added per-recording timestamp grouping: every OBS recording opens a numbered segment named after the OBS recording file, timestamps display as `R##-###` and restart at 001 each recording, and the Markdown log gains one section per recording.
- Session format bumped to version 3 with recording segments and per-timestamp segment stamps; version 1/2 files load unchanged with their entries shown under "Earlier timestamps".
- New WAV files are named `R##-###_HH-MM-SS.wav`; existing files keep their names.
- Added timestamp labels and preset tags (`keybinds.json`), editable through a per-timestamp dialog.
- Added timestamp deletion: the log entry is removed and the WAV file stays on disk.
- Added manual timestamps created from typed time positions (SS, MM:SS, or HH:MM:SS).
- Session format bumped to version 2 with optional label/tag fields; version 1 files load unchanged.
- Simplified the application to OBS-synchronized clickable timestamps.
- Added project names, project folders, Markdown logs, and JSON session metadata.
- Added microphone device selection and WAV recording/playback.
- Added configurable global timestamp hotkey.
- Bundled the sounddevice PortAudio runtime in the PyInstaller executable.
- Removed Gemini, screenshot, HUD, DaVinci Resolve, replay-buffer, video, and transcription features from the active application.
